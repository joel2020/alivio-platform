# LATAM / Medellín restoration evidence

Historical Google Web search, May 7, 2025–September 6, 2026: /nearshore-latam-recruiting had 3,356 impressions, 1 click, average position 15.5; /nearshore-latam-talent had 1,980 impressions, 1 click, position 14.9. Consolidate on the recruiting URL for explicit service intent and its greater visibility. /recruiting-agency-medellin had 1,100 impressions, 3 clicks, position 28.4; /recruiters-ny-medellin had 93 impressions, 1 click, position 10.8. Use the more visible city recruiting page as the destination. These are small traffic totals, not proven conversion channels.

The user approved this restoration after the recommendation. Two dedicated pages reuse existing search-page CSS and archived service scope. Each has distinct headings, introduction and body copy. No new local office, LocalBusiness/address/geo data, EOR/payroll integration, prices or performance claims. Shared intake means links to the existing /start page, not an embedded or inert form. Test traffic uses the existing mocked form requests; customers retain the working intake flow.

Before this change neither alias nor canonical was in the prerender list or sitemap. Sitemap baseline 82, expected net +2 = 84; only canonical pages added. Vercel uses existing redirects/rewrites, not legacy routes. No active links reference the aliases; the archived recovery component is not routed. Aliases have 308 deployment tests and client Navigate fallbacks.

Validation: both new no-JS checks failed on the old build for missing canonicals. Build emits 13 stable public pages plus 404. TypeScript and lint pass (one pre-existing SeoRecoveryPage Fast Refresh warning). Desktop LATAM and 390px Medellín visually reviewed; browser suite covers 320px overflow, axe accessibility, hydration, footer-to-intake navigation, sitemap/HTTP and redirects. Production/preview checks are run with PLAYWRIGHT_DEPLOYMENT=1. Local results and independent diff review are recorded on the PR. Rollback reference is production 905e5bbee8a561da520f11e48ea48dd862099ac4; revert restoration if production routing/intake/private-header regressions appear. Google submission targets only the two canonical pages, not aliases.

Independent plan review raised concerns based on missing context (assumed embedded intake, legacy routes and existing alias artifacts); the concrete implementation and checks above resolve them. Live results and Google submission outcomes are recorded on the PR after deployment.
